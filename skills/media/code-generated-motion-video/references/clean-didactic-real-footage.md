# Clean didactic explainer with real operational footage

Use for Carlos's approved explanatory style: light editorial motion, concrete visual steps and real footage, not a generic neon-card montage. This is an approved production pattern; do not claim every future variant is approved for publication.

## Narrative and visual contract
1. Open with one recognizable business friction, not an abstract AI promise.
2. Introduce the agent in one sentence with only demonstrated capabilities.
3. Explain setup: task, business context and explicitly authorized access.
4. Show a concrete task unfolding: input → action → result, synchronized to the exact narration beat.
5. Show integrations as connected tool nodes and moving payloads, not a wall of logos.
6. Present the report: completed actions, pendencies and requests for human approval.
7. Return to the person concentrating on their work, then a direct approved invitation.

Adapt the reference's sequence and clarity, never its brand, script or unsupported claims. Do not inherit telephone answering, universal integrations, zero missed customers, guaranteed revenue or complete autonomy from another product's advertisement.

## Look
- White/off-white base, black high-contrast sans-serif, aqua/lilac agent sphere or restrained brand accent, fine connectors and generous negative space.
- One main idea per beat; stagger reveals, animate actual UI state changes, and keep mobile text readable.
- Combine original motion/interface animation with at least two relevant real-footage inserts. Real footage must illustrate the adjacent line, not serve as unrelated decoration.
- Mark reconstructed interfaces as `Demonstração ilustrativa`. Do not portray fabricated interface data as evidence of a live completed operation.
- Blur/crop private names, phone numbers, email addresses and credentials before using recordings or packaging sources. Never include unsafe raw recordings in a delivery ZIP.
- Maintain the reference's structural coherence rather than copying its exact runtime. Around 60–75 seconds can support a complete explanation without rushed narration.

## Production
- Start with reference download/probe, transcript and contact sheet, then write an original scene-by-scene script with explicit visual provenance.
- Build deterministic seekable HTML/CSS/JS, capturing through Chromium/Playwright and compositing real footage through FFmpeg when appropriate. Name the actual renderer honestly: loading a Claude skill is not running Claude, and a failed HyperFrames command is not a HyperFrames render.
- Generate one consistent PT-BR voice or timed phrase clips from the same voice; keep approved original voice when supplied. Preserve natural speech and the full CTA; do not cram it into the render boundary.
- Export vertical 1080×1920, 30 fps, H.264/AAC and faststart, plus a lighter Telegram copy if needed. Subtitles stay readable and separate from the main interface text.
- Verify full decode, duration/audio, final-file CTA transcript, every real-footage insert and a contact sheet spanning all scenes. Inspect final frame, disclosure visibility and privacy blur.

## Reusable local implementation
Accepted implementation directory: `/root/gumercindo_didatico_reference/`.
- `index.html`: composition with `seek(t)` and `renderMode()`; capture motion separately and composite footage during finishing.
- `script.json`, `ROTEIRO.md`, `manifest.json`, `SOURCES.md`: narration, timeline, inputs and provenance.
- `produce.py`, `render.py`, `finish.py`, `fix_audio.py`: inspect the scripts before reuse; never rerun a costly TTS/generation step when validated audio is already present.
- Prepared privacy-safe footage: `assets/human.mp4`, `assets/operation.mp4`, `assets/focus.mp4`. Preserve originals; version new projects instead of overwriting the approved master.
- Verify the chosen project's interpreter and dependencies before reproducing its commands; preserve validated media and audio so environment repairs do not require paid regeneration.
- Check current renderer capabilities and report unknown usage as unknown. Obtain approval before substituting a platform the user explicitly required.

Publication remains a separate explicit authorization. Confirm target account, check for duplicates, preserve the upload's aspect ratio and read back the exact published post before reporting success.
