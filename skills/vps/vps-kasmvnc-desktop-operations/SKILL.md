# KasmVNC desktop na VPS

## Trigger
Use quando Carlos pedir para abrir algo no desktop da VPS (Chrome, WhatsApp Web) ou quando uma senha digitada por ele dentro do desktop for recusada. Para Instagram especificamente, veja a ressalva de bloqueio de IP abaixo antes de usar esse desktop.

**Instagram/Meta nesta VPS**: `instagram.com` frequentemente devolve `HTTP 429` persistente (não some com reload) a partir do IP desta VPS — bloqueio de reputação de IP de datacenter, não rate limit transitório. Não insista aqui; use o caminho do notebook Windows de Carlos (IP residencial) via `windows-hermes-mcp-worker-operations` / `remote-browser-login-handoff-carlos` para login ou automação de Instagram.

## Acesso
- Serviço `kasmvnc.service` (habilitado no boot), porta 6901, escutando **apenas** em `100.105.134.116` (tailnet). O backend direto é `http://100.105.134.116:6901`, mas para Carlos prefira uma rota HTTPS privada via Tailscale Serve em vez de mandar o HTTP direto: `tailscale serve --bg --https=9443 http://100.105.134.116:6901`, então entregue `https://srv1713101.tail0dcfcf.ts.net:9443`.
- Se o acesso privado falhar, diagnostique antes de criar túnel público: `systemctl is-active kasmvnc.service`, `ss -ltnp | grep ':6901'`, `curl --max-time 8 http://100.105.134.116:6901/` deve retornar `401`, `tailscale status --json` deve mostrar o notebook de Carlos online, e `tailscale ping <ip-do-notebook>` deve responder. Use Cloudflare/Funnel público só depois desses gates e com consentimento claro.
- Login/senha vêm de `/root/.secrets/kasmvnc.env` (modo 600); não assuma `root` se o arquivo tiver outro `KASMVNC_USER`. Entregar a senha como **arquivo** (MEDIA), nunca como texto no chat. Se Carlos estiver no celular e o teclado do KasmVNC sumir/travar, orientar a abrir o mesmo link em um computador antes de tentar rotas remotas mais complexas.
- Quando Carlos disser que o login do KasmVNC foi recusado, valide e, se necessário, gere uma credencial nova em `/root/.secrets/kasmvnc.env`, atualize `/root/gumercindo_war_room/acesso_desktop_vps_aros.txt` com modo 600, aplique permissão de escrita no banco do KasmVNC com `printf '%s\n%s\n' "$PASS" "$PASS" | vncpasswd -u "$USER_NAME" -w /root/.kasmpasswd`, reinicie `kasmvnc.service`, e verifique com `requests.get(URL, auth=(user, password))` esperando `200` e `<title>KasmVNC</title>`. Se o restart travar em “Provide user with write access”, faltou o `-w`.
- Nunca expor o desktop na internet pública como solução permanente: ele roda como root e tem acesso total à máquina.

## Regras de operação
- Chrome no desktop roda como root: usar sempre `--no-sandbox --test-type --password-store=basic` (sem `--no-sandbox` ele não abre; `--test-type` remove a faixa amarela de aviso).
- Layout de teclado: a sessão nasce em `us`. Corrija com `setxkbmap -layout br -variant abnt2` e persista no XFCE (`xfconf-query -c keyboard-layout -p /Default/XkbLayout -s br` e `-p /Default/XkbVariant -s abnt2`). Senha recusada por serviço (ex.: Instagram "The login information you entered is incorrect") é quase sempre layout errado, não senha errada.
- Chrome autofill reaproveita a senha salva: antes de testar de novo, o campo tem de ser apagado e digitado outra vez — senão o teste repete a senha antiga.
- `xdotool` **funciona** no Chrome desse desktop para clique e digitação: `xdotool mousemove X Y click 1` acerta botões e `xdotool type --clearmodifiers --delay 1 "$(cat arquivo.txt)"` preenche campos longos com segurança — confirme cada passo com print antes do próximo. Colar pela área de transferência **funciona** quando o alvo é uma área de conteúdo, não um campo isolado: `cat arquivo.tsv | xclip -selection clipboard -i` seguido de `xdotool key --clearmodifiers ctrl+v` entrega uma tabela inteira (multi-linha, colunas separadas por tab) na grade do Google Sheets de uma só vez — muito mais confiável que digitar célula por célula. Se após o `ctrl+v` o campo aparecer vazio, o problema é o **elemento focado** (input comum, widget do site), não o clipboard: aí escreva o texto num arquivo e digite com `xdotool type`. Regra prática: clipboard para volume de dados, `xdotool type` para um valor só. Passo a passo de planilha no navegador do desktop em `references/google-sheets-in-browser.md`. Para replicar uma base do Notion (base de dados nova, propriedades, colar TSV, caminhar coluna abaixo) use `references/notion-in-browser.md`. Para abrir uma página, inicie o Chrome com a URL direto: `subprocess.Popen(['google-chrome','--no-sandbox','--test-type', URL], env={**os.environ,'DISPLAY':':1','XAUTHORITY':'/root/.Xauthority'})`. **Mas se já existe um Chrome rodando nesse display, lançar o binário de novo com a URL frequentemente NÃO abre aba nenhuma** — a janela existente segue mostrando as mesmas abas antigas e parece que o comando não fez nada (compare prints antes/depois; o processo novo aparece no `ps`, a aba não). Nesse caso abra a aba dentro da janela viva com `xdotool`: `xdotool search --onlyvisible --class google-chrome | head -1 | xargs -I{} xdotool windowactivate --sync {}`, depois `xdotool key --clearmodifiers ctrl+t`, `xdotool type --clearmodifiers --delay 1 "$(cat /tmp/url.txt)"` e `xdotool key --clearmodifiers Return`. Grave a URL num arquivo antes de digitar: `?`, `&` e `%` quebram o quoting do shell se forem inline.
- Quando Carlos precisa fazer login manual em um site, não use `browser_exec` como handoff visual — ele abre um navegador isolado que Carlos não vê no KasmVNC. Abra o site no Chrome do display `:1` com `DISPLAY=:1 XAUTHORITY=/root/.Xauthority HOME=/root google-chrome --no-sandbox --test-type --no-first-run --password-store=basic '<URL>'`, depois capture um print real da sessão para confirmar que a tela visível dele mudou.
- Primeira execução do Chrome: pede aceite de termos (ative a janela do diálogo e envie `Return`) e em seguida mostra o promo "Sign in to Chrome" — usar `--no-first-run` para evitar.
- Descobrir o `XAUTHORITY` certo: `ps aux | grep -oE '\-auth [^ ]+'` pega o `-auth` de **qualquer** processo e devolve lixo (um arquivo de `xvfb-run`). Leia o flag da linha do **Xvnc** (`ps aux | grep Xvnc`) — nesta VPS é `-auth /root/.Xauthority`, o valor que funciona para print e para abrir janelas.
- Clientes de visualização do Carlos pode redimensionar a tela (allow_resize); confira `xdpyinfo | grep dimensions` antes de calcular coordenadas de clique.
- Para abrir o Chrome (ou qualquer app) em segundo plano nesta VPS, nunca encadeie `&`, `nohup` ou `setsid ... &` dentro do comando passado ao `terminal` — a ferramenta rejeita wrappers de backgrounding em shell ("Foreground command uses shell-level background wrappers") porque ela mesma rastreia o processo. Chame `terminal(command="export DISPLAY=:1 XAUTHORITY=/root/.Xauthority HOME=/root; google-chrome --no-sandbox --test-type --no-first-run --password-store=basic 'URL'", background=True, notify=True)` sem `&`/`setsid` no comando, depois confirme com um print — o processo roda sob o controle do próprio Hermes.
- Para apps densos de uma página só (Bubble.io, dashboards React com elementos sobrepostos/invisíveis), cliques por coordenada do `xdotool` acertam o elemento errado mesmo com print confirmando a posição visual — o DOM real pode ter várias camadas empilhadas no mesmo pixel. Nesses casos, abra um Chrome próprio no mesmo display com `--remote-debugging-port=9222 --user-data-dir=<cópia do profile logado>` e controle via CDP bruto (WebSocket, sem lib externa) usando `Runtime.evaluate`: liste elementos com `getBoundingClientRect()` para achar o seletor certo, dispare `.click()`/preencha `.value` + `dispatchEvent(new Event('input'))` direto no DOM, e leia `document.body.innerText` para confirmar o resultado. Isso é muito mais confiável que repetir cliques por pixel. Use `scripts/cdp_eval.py` (lê JS do stdin, devolve o resultado de `Runtime.evaluate`) — clone o `user-data-dir` da sessão já logada antes de abrir o Chrome de debug, senão perde a sessão.
- Conectar via `websocket-client` (Python) num Chrome `--remote-debugging-port` lançado nesta VPS dá `403 Forbidden` ("Rejected an incoming WebSocket connection from the http://127.0.0.1:PORT origin") a menos que o Chrome tenha sido iniciado com `--remote-allow-origins=*`; sem essa flag só o DevTools frontend oficial conecta. Ao abrir `websocket.create_connection(...)`, passe também `origin='http://127.0.0.1:PORT'`. Para enviar arquivo a um `<input type=file>` via CDP, não dá para setar `.value` por JS (bloqueado por segurança do browser); use `DOM.getDocument(depth=-1, pierce=True)` + `DOM.querySelector` para achar o `nodeId` do input e `DOM.setFileInputFiles(nodeId=..., files=[caminho])` — repita a busca do nodeId a cada upload porque o DOM pode remontar entre modais.
- Formulários SPA que escondem `<textarea>` atrás de um editor rich-text (TinyMCE/ProseMirror) não aceitam `textarea.value=...; dispatchEvent('input')` — o editor visível é um `<iframe>` e o textarea real fica `display:none`, então o app ignora a mudança e mostra "campo obrigatório". Para TinyMCE especificamente, use `tinymce.activeEditor.setContent(htmlString)` seguido de `.save()` e `.fire('change')`/`.fire('input')` no `Runtime.evaluate`.

## Login interativo de CLI dentro do desktop (código não passa pelo chat)
Quando um CLI pede login por OAuth e devolve um **código para colar** (Claude Code e qualquer outro com o mesmo desenho), rode o fluxo dentro do desktop: quem cola o código é o Carlos, ali na tela, e o valor nunca entra no chat.
1. Escreva um script que exporte `DISPLAY=:1 XAUTHORITY=/root/.Xauthority HOME=/root`, imprima as instruções e rode o comando com `| tee /tmp/<nome>_saida.txt` — o link/URL sai do arquivo, sem depender de ler a tela.
2. Abra o terminal no desktop com `terminal(command="env DISPLAY=:1 XAUTHORITY=/root/.Xauthority HOME=/root xfce4-terminal --title='<titulo>' --geometry=110x30 -x /root/<script>.sh", background=True)` — sem `setsid`/`&` no comando (o `terminal` tool rejeita wrappers de backgrounding em shell; `background=True` já cuida disso).
3. Opcional: abrir a URL capturada do `tee` num Chrome próprio do desktop — `google-chrome --no-sandbox --no-first-run --user-data-dir=/root/.config/chrome-<uso> "$URL"`.
4. Entregue ao Carlos **o link** (ele abre no celular, onde já está logado) + a instrução de colar o código no terminal do desktop que está aberto. Nunca pedir o código no chat.
5. Confirme com o status do próprio CLI (ex.: `claude auth status`) e depois com uma chamada real — "terminal aberto e esperando" não é login concluído.
6. **Variante OAuth com redirect para `localhost` (Google Workspace, Claude Code e qualquer app com `redirect_uri=http://localhost:...`): não faça o usuário colar o código.** O redirect resolve para a máquina que roda o browser, então suba um listener mínimo na **mesma porta** e na **mesma máquina** do Chrome do desktop (como root a porta 1 é vinculável; confirme com `ss -ltnp | grep ':1 '`) que grave `code=`/`state=`/`error=` num arquivo e devolva uma página "autorização recebida"; conduza o consentimento no Chrome do desktop (é ali que ele digita a senha), depois leia o código do arquivo e faça a troca você mesmo. O código nunca é digitado nem colado por ele e nunca entra no chat. **Arquivo de captura vazio = o consentimento nunca chegou ao redirect**: tire o print do desktop antes de qualquer nova tentativa, porque o caso comum é o próprio provedor ter bloqueado a tela (conta fora dos *test users* de um app em modo de teste, erro 403 `access_denied`) ou o navegador ainda estar no "Choose an account"; não regenere o link nem repita a troca às cegas.

## Verificação obrigatória
- Print real da sessão: `ffmpeg -hide_banner -loglevel error -f x11grab -video_size <resolução atual> -i :1 -frames:v 1 /tmp/x.png` com `DISPLAY=:1 XAUTHORITY=/root/.Xauthority`; liste os apps abertos com `xlsclients`. Sem `-video_size`, ou com valor diferente da sessão, o print sai preto/cortado. Depois de reiniciar o Chrome, um popup "Restore pages?" pode cobrir a página — feche no X e tire outro print antes de concluir o que está na tela.
- Olhe o PNG antes de afirmar que abriu. Nunca dizer "abriu" só porque o comando rodou sem erro (o caso comum é o Chrome abrir e a página não carregar).

## Segurança
- Não digitar, pedir nem aceitar a senha de Carlos no chat; ele loga manualmente no desktop. Ao ver checkpoint/2FA do Instagram/Meta, pare e devolva a decisão para ele.
- Código de autorização/OAuth de qualquer CLI ou site é credencial: quem digita é ele, dentro do desktop. O agente informa **onde** colar; nunca recebe o valor.
- Para SaaS com login por código de e-mail quando o prompt seguro não estiver disponível, use `references/saas-otp-handoff.md`.
